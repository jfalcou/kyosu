Rotations

A unit quaternion represents a rotation of the three-dimensional space, and is the standard representation of rotations in graphics, robotics, and aerospace.

Constructors

The rotation of angle \(\theta\) about the unit axis \(u\) is the quaternion \(q = \cos\frac{\theta}{2} + \sin\frac{\theta}{2}\,(u_x i + u_y j + u_z k)\), which kyosu::from_angle_axis builds from \(\theta\) and \(u\):

A quaternion can be built from an angle and an axis, from Euler angles with their axes, from a modulus, an argument, and a unit pure quaternion, or from the spherical and cylindrical coordinates of the four-dimensional space:

#include <array>
#include <iostream>
#include <kyosu/kyosu.hpp>
#include <span>
int main()
{
auto pi = eve::pi(eve::as<double>());
// A rotation of pi/3 around the axis (1,2,3).
std::array<double, 3> axis{1., 2., 3.};
std::cout << "from_angle_axis = " << kyosu::from_angle_axis(pi/3, std::span(axis)) << "\n";
// The same idea through Euler angles, naming the three axes used.
std::cout << "from_euler = "
<< kyosu::from_euler(pi/2, pi/3, pi/4, kyosu::Z_, kyosu::X_, kyosu::Z_) << "\n";
// Modulus, argument, and the unit pure quaternion that plays the part of i.
auto u = kyosu::quaternion_t<double>(0., 1., 2., 2.) / 3.;
std::cout << "from_polar = " << kyosu::from_polar(2., pi/6, u) << "\n";
// Four-dimensional spherical and cylindrical parametrisations.
std::cout << "from_spherical = " << kyosu::from_spherical(1., pi/4, pi/3, pi/6) << "\n";
std::cout << "from_cylindrical = " << kyosu::from_cylindrical(1., pi/4, 2., 3.) << "\n";
}

Comparison with Euler angles

Three angles around three axes represent a rotation with two defects. The first is gimbal lock: at some orientations two of the three axes align, and a direction of motion is no longer reached by varying the angles. The second concerns interpolation: a linear interpolation of the three angles is not the shortest path between the two rotations, and has neither a fixed axis nor a constant angular speed. A unit quaternion has neither defect: it covers every orientation without a singularity, it composes by multiplication, and two of them interpolate along the shortest arc.

Rotating a vector

The rotation sends a vector \(v\) to \(v' = q v q^{-1}\), which kyosu::rotate_vec computes. The angle of kyosu::from_angle_axis is in radians. kyosu::rotate_vec takes the vector as an array of three reals passed as a std::span, and returns the rotated vector as a std::array:

#include <array>
#include <iostream>
#include <kyosu/kyosu.hpp>
#include <span>
int main()
{
auto pi = eve::pi(eve::as<double>());
std::array<double, 3> axis{0., 0., 1.}; // the z axis
std::array<double, 3> v {1., 0., 0.}; // the x axis
auto q = kyosu::from_angle_axis(pi/2, std::span(axis));
auto rv = kyosu::rotate_vec(q, std::span(v));
std::cout << "q = " << q << "\n";
std::cout << "v = (" << v[0] << ", " << v[1] << ", " << v[2] << ")\n";
std::cout << "rotate_vec = (" << rv[0] << ", " << rv[1] << ", " << rv[2] << ")\n";
}

A positive angle turns counterclockwise about the axis, by the right-hand rule: the quarter turn about \(z\) sends \(x\) to \(y\).

Note
kyosu::from_angle_axis normalizes the axis, and kyosu::rotate_vec the quaternion, so that neither argument has to be of unit length. The option kyosu::assume_unitary skips the normalization on an argument already of unit length.

Composition

The rotation \(p\) followed by \(q\) is the product \(qp\), in that order, since the product does not commute. A rotation composed backward is the usual effect of a product written in the wrong order, or of one division taken for the other:

#include <array>
#include <iostream>
#include <kyosu/kyosu.hpp>
#include <span>
int main()
{
auto pi = eve::pi(eve::as<double>());
std::array<double, 3> z{0., 0., 1.}, y{0., 1., 0.};
auto p = kyosu::from_angle_axis(pi/2, std::span(z)); // quarter turn about z
auto q = kyosu::from_angle_axis(pi/2, std::span(y)); // quarter turn about y
std::array<double, 3> v{1., 0., 0.};
// p first, then q, is the single rotation q*p.
auto a = kyosu::rotate_vec(q * p, std::span(v));
auto b = kyosu::rotate_vec(p * q, std::span(v));
std::cout << "q*p applied to x = (" << a[0] << ", " << a[1] << ", " << a[2] << ")\n";
std::cout << "p*q applied to x = (" << b[0] << ", " << b[1] << ", " << b[2] << ")\n";
}

Interpolation

kyosu::slerp, the spherical linear interpolation, interpolates between two orientations along the shortest arc at constant angular speed, which is the interpolation an animation or a trajectory requires. Since \(q\) and \(-q\) are the same rotation, the sign of the second operand is chosen so that the arc is the short one:

#include <array>
#include <iostream>
#include <kyosu/kyosu.hpp>
#include <span>
int main()
{
auto pi = eve::pi(eve::as<double>());
std::array<double, 3> z{0., 0., 1.};
auto q0 = kyosu::from_angle_axis(0., std::span(z)); // no rotation
auto q1 = kyosu::from_angle_axis(pi/2, std::span(z)); // a quarter turn
std::array<double, 3> v{1., 0., 0.};
for (double t = 0.; t <= 1.0001; t += 0.25)
{
auto rv = kyosu::rotate_vec(kyosu::slerp(q0, q1, t), std::span(v));
std::cout << "t = " << t << " -> (" << rv[0] << ", " << rv[1] << ", " << rv[2] << ")\n";
}
}

Conversions

A rotation converts to and from a rotation matrix, with kyosu::to_rotation_matrix and kyosu::from_rotation_matrix, Euler angles with their axes, with kyosu::to_euler and kyosu::from_euler, and an angle and an axis, with kyosu::to_angle_axis and kyosu::from_angle_axis. The matrix is a std::array of three rows. The angle and the axis, and the three Euler angles, are returned as a kumi::tuple, read by a structured binding:

#include <array>
#include <iostream>
#include <kyosu/kyosu.hpp>
#include <span>
int main()
{
auto pi = eve::pi(eve::as<double>());
std::array<double, 3> axis{0., 0., 1.};
auto q = kyosu::from_angle_axis(pi/3, std::span(axis));
std::cout << "q = " << q << "\n";
// Back to an angle and an axis.
auto [angle, ax] = kyosu::to_angle_axis(q);
std::cout << "to_angle_axis = " << angle << " rad about ("
<< ax[0] << ", " << ax[1] << ", " << ax[2] << ")\n";
// To Euler angles, naming the three axes, and back again.
auto [a, b, c] = kyosu::to_euler(q, kyosu::Z_, kyosu::X_, kyosu::Z_);
std::cout << "to_euler = " << a << ", " << b << ", " << c << "\n";
std::cout << "round trip = " << kyosu::from_euler(a, b, c, kyosu::Z_, kyosu::X_, kyosu::Z_) << "\n";
// To a rotation matrix, and back.
auto m = kyosu::to_rotation_matrix(q);
std::cout << "to_rotation_matrix =\n";
for (int i = 0; i < 3; ++i)
std::cout << " " << m[i][0] << ", " << m[i][1] << ", " << m[i][2] << "\n";
std::cout << "from_rotation_matrix = " << kyosu::from_rotation_matrix(m) << "\n";
}

The Euler angles are in radians. The three axes that follow them are listed in the order of the three rotations, the first angle going with the first axis, and each is one of kyosu::X_, kyosu::Y_, and kyosu::Z_, two consecutive axes being distinct. Each rotation is about the axis as moved by the rotations before it, which is the intrinsic reading of the angles. The option kyosu::extrinsic reads them about the fixed axes instead, and kyosu::radpi takes them as multiples of \(\pi\).

A round trip through a matrix or a triple of angles may return \(-q\) in place of \(q\).
