Options

Some functions have different behaviors depending on the context:

  • kyosu::sqrt may return \(i\) or a NaN on \(-1\),
  • kyosu::to_euler may return its angles in radians or in multiples of \(\pi\),
  • kyosu::log may evaluate with full accuracy, or by a faster formula with less precision,
  • kyosu::rotate_vec assumes its quaternion is not normalized, but it may be.

A specific function for each behavior would dilute the API, so KYOSU reuses the option mechanism of EVE:

kyosu::sqrt[kyosu::real_only](-1.0)

Options, which modify the semantics of a function, are passed in square brackets after its name. kyosu::sqrt[kyosu::real_only] is a new callable, which is then applied to the arguments.

Options compose, as in kyosu::to_euler[kyosu::extrinsic][kyosu::radpi]. A function of its own for that combination, to_euler_extrinsic_radpi, would be obscure in the API.

raw

By default a function is accurate over its whole domain and handles the edges of that domain. kyosu::raw selects the fastest formula instead, with two effects:

  • less accuracy on ordinary input,
  • no handling of the edges.

Below, kyosu::log and kyosu::log[kyosu::raw] are applied to an ordinary value and to the origin, where the default returns an imaginary part and the option a NaN:

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
using c_t = kyosu::complex_t<double>;
// An ordinary value, inside the domain.
auto z = c_t(3., 4.);
std::cout << "log(z) = " << kyosu::log(z) << "\n";
std::cout << "log[raw](z) = " << kyosu::log[kyosu::raw](z) << "\n";
// At the origin, the default returns an imaginary part and the raw formula a NaN.
auto o = c_t(0., 0.);
std::cout << "log(0) = " << kyosu::log(o) << "\n";
std::cout << "log[raw](0) = " << kyosu::log[kyosu::raw](o) << "\n";
}

radpi

By default, angles are in radians. An angle such as \(\pi/2\) is then an irrational number, which no floating point number represents exactly, so pi/2 already carries a rounding error. kyosu::radpi reads and returns angles as multiples of \(\pi\) instead, with two effects:

  • 0.5 stands for \(\pi/2\) exactly,
  • the result carries no rounding error of \(\pi\).

Below, kyosu::sin is applied to a half turn and to a million half turns, where the sine is zero, in radians and with the option:

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
auto pi = eve::pi(eve::as<double>());
auto z = kyosu::complex_t<double>(1., 0.);
// A half turn, where the sine is zero.
std::cout << "sin(pi * z) = " << kyosu::sin(pi * z) << "\n";
std::cout << "sin[radpi](z) = " << kyosu::sin[kyosu::radpi](z) << "\n";
// A million half turns: the rounding error of pi grows with the angle.
std::cout << "sin(1e6 * pi * z) = " << kyosu::sin(1e6 * pi * z) << "\n";
std::cout << "sin[radpi](1e6 * z) = " << kyosu::sin[kyosu::radpi](1e6 * z) << "\n";
}

real_only

By default, a real argument outside the real domain of a function gives a complex result. kyosu::real_only selects the real function instead, with two effects:

  • the result is a real,
  • an argument outside the real domain gives a NaN.

Below, kyosu::acosh and kyosu::asin are applied to arguments outside their real domains, with and without the option:

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
std::cout << "acosh(0.5) = " << kyosu::acosh(0.5) << "\n";
std::cout << "acosh[real_only](0.5) = " << kyosu::acosh[kyosu::real_only](0.5) << "\n";
std::cout << "asin(2.0) = " << kyosu::asin(2.0) << "\n";
std::cout << "asin[real_only](2.0) = " << kyosu::asin[kyosu::real_only](2.0) << "\n";
}

assume_unitary

By default, kyosu::from_angle_axis and kyosu::rotate_vec normalize their argument, since a rotation is a unit quaternion. kyosu::assume_unitary skips that normalization on an argument known to be of unit length, with two effects:

  • kyosu::from_angle_axis uses its axis as given,
  • kyosu::rotate_vec uses its quaternion as given.

Below, kyosu::rotate_vec is applied to a unit quaternion, with and without the option:

#include <array>
#include <iostream>
#include <kyosu/kyosu.hpp>
#include <span>
int main()
{
auto pi = eve::pi(eve::as<double>());
std::array<double, 3> axis{0., 0., 1.};
std::array<double, 3> v{1., 0., 0.};
auto q = kyosu::from_angle_axis(pi/2, std::span(axis)); // already unitary
std::cout << "abs(q) = " << kyosu::abs(q) << "\n";
auto a = kyosu::rotate_vec(q, std::span(v));
auto b = kyosu::rotate_vec[kyosu::assume_unitary](q, std::span(v));
std::cout << "rotate_vec = (" << a[0] << ", " << a[1] << ", " << a[2] << ")\n";
std::cout << "rotate_vec[assume_unitary] = (" << b[0] << ", " << b[1] << ", " << b[2] << ")\n";
}
