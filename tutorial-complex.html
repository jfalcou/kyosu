Complex numbers

KYOSU supports complex numbers via kyosu::complex_t<T>, where T is a floating point type.

Construction and printing

A complex number is built from its real and imaginary parts:

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
auto z = kyosu::complex_t<double>(3., 4.);
std::cout << "z = " << z << "\n";
std::cout << "real(z) = " << kyosu::real(z) << "\n";
std::cout << "imag(z) = " << kyosu::imag(z) << "\n";
std::cout << "conj(z) = " << kyosu::conj(z) << "\n";
std::cout << "abs(z) = " << kyosu::abs(z) << "\n";
std::cout << "arg(z) = " << kyosu::arg(z) << "\n";
std::cout << "z * z = " << z * z << "\n";
}

A value prints as \(3 + 4i\), each component followed by the symbol of its basis element, rather than as the pair \((3,4)\) of std::complex. The functions above behave as their namesakes on std::complex:

  • kyosu::real and kyosu::imag return the two components,
  • kyosu::conj returns the conjugate,
  • kyosu::abs returns the modulus,
  • kyosu::arg returns the argument.

Elementary functions

The standard arithmetic and the elementary functions are available on complex numbers, in namespace kyosu, under the names of their real counterparts. There are two hundred functions, from the arithmetic and the transcendental functions to the special functions:

  • the Riemann zeta function, kyosu::zeta,
  • the Legendre polynomials, kyosu::legendre,
  • the elliptic integrals, kyosu::ellint_fe for Legendre's forms, and kyosu::ellint_rc, kyosu::ellint_rd, kyosu::ellint_rf, kyosu::ellint_rg, and kyosu::ellint_rj for Carlson's.
#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
auto z = kyosu::complex_t<double>(0.5, 0.25);
std::cout << "exp(z) = " << kyosu::exp(z) << "\n";
std::cout << "log(z) = " << kyosu::log(z) << "\n";
std::cout << "sin(z) = " << kyosu::sin(z) << "\n";
std::cout << "tanh(z) = " << kyosu::tanh(z) << "\n";
std::cout << "erf(z) = " << kyosu::erf(z) << "\n";
std::cout << "tgamma(z) = " << kyosu::tgamma(z) << "\n";
std::cout << "zeta(z) = " << kyosu::zeta(z) << "\n";
std::cout << "legendre(3, z) = " << kyosu::legendre(3, z) << "\n";
}

Real arguments

A function applied to a real argument outside its real domain returns a complex result. For example, kyosu::sqrt(-1.0) returns \(i\), where std::sqrt(-1.0) returns NaN.

The return type widens from double to kyosu::complex_t<double>, so that the result is not lost.

Note
The option kyosu::real_only selects the real function and its NaN instead:
#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
// By default a real argument outside the real domain widens to a complex answer.
std::cout << "sqrt(-1.0) = " << kyosu::sqrt(-1.0) << "\n";
std::cout << "log(-1.0) = " << kyosu::log(-1.0) << "\n";
std::cout << "acos(2.0) = " << kyosu::acos(2.0) << "\n";
// real_only asks for the real function instead, NaN included.
std::cout << "sqrt[real_only](-1.0) = " << kyosu::sqrt[kyosu::real_only](-1.0) << "\n";
std::cout << "log[real_only](-1.0) = " << kyosu::log[kyosu::real_only](-1.0) << "\n";
std::cout << "acos[real_only](2.0) = " << kyosu::acos[kyosu::real_only](2.0) << "\n";
}

Comparison

Complex numbers are compared for equality and tested by the componentwise predicates. No < is defined: the complex numbers are not an ordered field, no total order of the plane being compatible with both their addition and their multiplication:

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
auto z = kyosu::complex_t<double>(3., 4.);
auto w = kyosu::complex_t<double>(3., 0.);
std::cout << std::boolalpha;
std::cout << "z == w : " << (z == w) << "\n";
std::cout << "is_real(w) : " << kyosu::is_real(w) << "\n";
std::cout << "is_pure(z) : " << kyosu::is_pure(z) << "\n";
std::cout << "is_finite(z) : " << kyosu::is_finite(z) << "\n";
}
