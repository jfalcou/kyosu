Octonions and beyond

Nothing in the construction stops at four dimensions. A pair of quaternions gives an octonion, a pair of octonions a sedenion, and so on without end. KYOSU implements the whole tower, so this page is about what changes as you climb it — and about the two places where habits acquired on real numbers will mislead you.

The mathematics is set out properly in Mathematics of Cayley-Dickson Algebras. Here we only look at the code.

Naming any dimension

Past the octonions the basis elements stop having traditional names and are simply indexed. The type is named by its dimension:

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
auto o = kyosu::octonion_t<double>(1., 2., 3., 4., 5., 6., 7., 8.);
// Past dimension 8 the type is named by its dimension.
using s_t = kyosu::as_cayley_dickson_n_t<16, double>;
s_t s{};
kyosu::get<0>(s) = 1.;
kyosu::get<9>(s) = 2.;
std::cout << "octonion : " << o << "\n";
std::cout << "sedenion : " << s << "\n";
std::cout << "abs(o) = " << kyosu::abs(o) << "\n";
std::cout << "exp(s) = " << kyosu::exp(s) << "\n";
}

First trap: parentheses are load-bearing

From dimension 8 on, \((ab)c\) and \(a(bc)\) are different numbers. This is not a rounding difference — the sign of a whole component flips:

#include <iostream>
#include <kyosu/kyosu.hpp>
using o_t = kyosu::octonion_t<double>;
template<int N> o_t e() { o_t z{}; kyosu::get<N>(z) = 1.; return z; }
int main()
{
auto a = e<1>(), b = e<2>(), c = e<4>();
std::cout << "(ab)c = " << (a*b)*c << "\n";
std::cout << "a(bc) = " << a*(b*c) << "\n";
std::cout << "associator = " << kyosu::associator(a, b, c) << "\n";
// On quaternions the associator vanishes: they are associative.
auto q = kyosu::quaternion_t<double>(1., 2., 3., 4.);
std::cout << "on quaternions = " << kyosu::associator(q, q*q, q+q) << "\n";
}

kyosu::associator computes \((ab)c - a(bc)\) directly, so the defect can be measured. On quaternions and below it is zero; on octonions it is not. KYOSU never re-associates an expression, so what you write is what is evaluated — which also means that a refactoring which looks harmless can change the answer.

Second trap: from dimension 16, division fails

Octonions still form a division algebra: every non-zero element has an inverse. Sedenions do not. There exist non-zero values whose product is zero, and neither of them can be inverted:

#include <iostream>
#include <kyosu/kyosu.hpp>
using s_t = kyosu::as_cayley_dickson_n_t<16, double>;
template<int N> s_t e() { s_t z{}; kyosu::get<N>(z) = 1.; return z; }
int main()
{
auto a = e<3>() + e<10>();
auto b = e<6>() - e<15>();
std::cout << "|a| = " << kyosu::abs(a) << "\n";
std::cout << "|b| = " << kyosu::abs(b) << "\n";
std::cout << "|a*b| = " << kyosu::abs(a*b) << "\n";
// The product destroys the operands, and no division brings them back.
std::cout << "|ldiv(b, a*b)| = " << kyosu::abs(kyosu::ldiv(b, a*b))
<< " but |a| = " << kyosu::abs(a) << "\n";
}

Two perfectly finite operands, each of norm \(\sqrt2\), with a product of exactly zero.

Note what the trap is not. Nothing overflows, no NaN appears, and no exception is raised: the answer is a finite, ordinary-looking zero. The multiplication has simply destroyed its operands, and dividing back by \(b\) returns zero rather than \(a\). Above dimension 8 an algebraic identity you would never think to question — that \(ab\) determines \(a\) once \(b\) is known — no longer holds, and nothing in the output will tell you.

What still works everywhere

It would be reasonable to conclude that high dimensions are unusable. They are not, because the property the elementary functions actually need survives at every level: the subalgebra generated by a single element is always associative. So powers, exponentials, logarithms and everything built on them remain well defined however far you go.

#include <iostream>
#include <kyosu/kyosu.hpp>
int main()
{
using s_t = kyosu::as_cayley_dickson_n_t<32, double>;
s_t z{};
kyosu::get<0>(z) = 0.5;
kyosu::get<7>(z) = 0.25;
// A single element always generates an associative subalgebra, so these stay meaningful.
std::cout << "exp(log(z)) = " << kyosu::exp(kyosu::log(z)) << "\n";
std::cout << "z = " << z << "\n";
std::cout << "sqrt(z)^2 = " << kyosu::sqr(kyosu::sqrt(z)) << "\n";
}
